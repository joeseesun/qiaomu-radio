# 乔木电台 PRD

## 当前界面契约（2026-09-13 修订，优先于下文初版布局）

顶部仅显示主题切换。点击主题后，完整功能收进一台播放器：iPod 是完整机身与圆盘，Winamp 和 foobar2000 是独立桌面窗口。页面不显示外围介绍、心情区、推荐侧栏或统计。

搜索、频道选择、电台列表、喜欢/不喜欢、历史、音量、来源说明和错误提示均在机内显示。iPod 的 MENU 返回/打开菜单，左右键移动条目，中心键选择；其他主题用窗口内工具栏。选择心情或中国源保留当前机身。切换主题保留偏好与音量，自动启动该主题系列，失效时说明并自动换台。

## AI 速读卡

- 产品一句话：选择一种播放器风格或心情，进入会随反馈调整的全球与中国直播电台流。
- 核心循环：选心情 → 听直播 → 喜欢/跳过 → 调整标签权重 → 下一家更合口味。
- 目标平台：桌面与移动浏览器，本地优先。
- 硬约束：不伪造歌曲级元数据；不代理未知音频 URL；不上传口味数据。
- 推荐默认：6 个心情频道、无账号、本地口味模型、HTTPS 流优先。
- 发挥空间：换台过渡、编辑文案、封面降级和空状态。
- P0 验收：用户点击任一播放器风格后，界面切换并自动开播；单台失效时说明原因并自动换台。
- 最容易翻车：把“电台推荐”误说成“歌曲推荐”；直播流失效时不给恢复路径。
- 超预期机会：不要表单式口味设置，让“听”本身慢慢成为用户的频率画像。

## 第一章：产品概述

乔木电台是一款个性化直播电台，让不想反复选歌的用户能够从一个心情出发持续收听，而无需理解频道、标签和播放列表。

### 1.1 差异化对比表

| 功能 | 竞品 | 本产品 | 实现方式 |
|---|---|---|---|
| 内容单元 | Pandora/豆瓣 FM 的心智是曲目序列 | 可验证的全球直播电台 | Radio Browser `stations/search` |
| 个性化 | 基于曲目与版权曲库（此处不比较其当前算法） | 基于电台标签、跳过和近期收听 | 本地权重模型 + 近期去重 |
| 用户数据 | 通常需账号才能跨端 | P0 不需账号 | `localStorage` 只存本机 |
| 失效恢复 | 曲库内容可控 | 直播天生不稳定，必须面向失败设计 | 健康过滤、镜像切换、失败队列 |

已验证事实：Radio Browser 文档提供高级电台搜索、`hidebroken`、随机排序、多镜像和播放计数端点；服务会定期检查电台可用性。来源：https://docs.radio-browser.info/。

### 1.2 三类用户画像

| 角色 | 核心目标 | 对现有工具最大的不满 | 愿意切换的一个功能 |
|---|---|---|---|
| 伴随型工作者 | 不打断注意力地听几小时 | 每隔几分钟选歌 | 一个心情即可开始的连续直播 |
| 音乐漫游者 | 遇见不同地区的真实声音 | 流媒体推荐越来越封闭 | 下一家的全球电台漫游 |
| 怀旧广播听众 | 找到熟悉城市或电台 | 网页播放器分散、记不住 | 搜索 + 最近收听 + 喜欢 |

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
|---|---|
| 按心情、名称和标签找直播电台 | 按曲点播：Radio Browser 是流索引，不是版权曲库 |
| 对电台级标签学习口味 | 曲目级准确推荐：许多流不稳定返回曲目元数据 |
| 浏览器支持的 HTTP(S) 音频直播 | 保证所有电台可播：编码、地区限制、证书和宕机均不可控 |
| 本地历史和口味导出的 P1 扩展 | 账号、付费、社交和无限后台代理：P0 不需要，且会放大隐私与运营风险 |
| 审核后的广播机构公开 HTTPS/HLS 中国源 | 抓包或逆向蜻蜓 FM、云听等封闭平台：没有公开 API 授权 |

### 1.5 主题与中国源增量

| 主题 | 结构语言 | 默认系列 | 点击结果 |
|---|---|---|---|
| 编辑部 | 大封面、留白、衬线标题 | Focus | 切换并开播 |
| 随身听 | 单色屏、白色外壳、圆盘 | Jazz | 切换并开播 |
| 像素甲板 | 频谱、像素字、紧凑按钮 | Energy | 切换并开播 |
| 音频控制台 | 电平表、密集读数、工具栏 | Classical | 切换并开播 |
| 中国波段 | 模拟刻度、宋体、广播红 | 中国审核白名单 | 切换并开播 |

失败流程：`主题点击 → 候选 1 → 15 秒超时/解码失败 → 用户可见提示 → 候选 2 … → 最多 5 家 → 明确终止错误`。直播中途断流也沿同一候选序列自动后移。

中国源治理：只保存广播机构自有域名的公开 HTTPS URL、官网与基本元数据；不把 GitHub M3U 合集直接作为线上依赖，不抓取封闭平台，不承诺永久可用。HLS 在 Safari 使用原生能力，在其他支持 MSE 的浏览器使用 `hls.js`。

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
|---|---|---|
| 播放为首要任务；每次开播调用 click counter；不上传偏好；不伪造曲目 | 6 个心情；本地模型；镜像失败切换；HTTPS 优先 | 封面、缓冲动效、编辑文案、个性化说明方式 |

## 第四章：超越竞品的差异化功能

### 第 4.1 节 无表单的口味建模

1. 竞品为何没有这个功能：基于公开信息的推断，曲库型产品有更完整的歌曲/艺人信号，而开放直播索引只有不规整的电台标签；把不完整性变成渐进反馈是本产品的结构性机会。
2. 本产品如何实现：喜欢使前 6 个标签权重 +1，不喜欢使其 -1.5；加上 HTTPS、点击数、投票数和随机探索项。
3. 交互流程：`收听 → 一次反馈 → 无需打断播放 → 下一家重排`。
4. 风险与应对：标签噪声会造成过度收窄；通过权重上下限、随机探索和近期去重保留多样性。

### 第 4.2 节 把失效当作直播的一部分

1. 竞品为何没有这个功能：基于公开信息的推断，可控曲库里播放失败是异常；开放直播中流迁移、宕机和地区限制是常态。
2. 本产品如何实现：`hidebroken=true` 作为第一道过滤；实播失败放入会话级排除集；目录请求按固定镜像序列失败转移。
3. 交互流程：`播放失败 → 说明哪家中断 → 标记失败 → 一键下一家`。
4. 风险与应对：不自动无限跳转，避免用户不知道系统正在做什么；只展示具体恢复动作。

### 超预期机会

- 收听 20 分钟后，生成一句不外传的本地频率摘要，例如“你正在靠近爵士和慢速器乐”。
- 每次换台保留一条“从多伦多到苏黎世”的地理过渡文案，不需要地图。
- 允许把本地口味导出为可读 JSON，用户始终拥有自己的数据。

## 第五章：数据模型

```jsonc
{
  "version": "1", // 必填；本地数据结构版本
  "selectedMood": "focus", // 必填；默认值: focus；6 个 MoodId 之一
  "likedStationIds": {"960cf833-0601-11e8-ae97-52543be04c81": true}, // 必填；用户喜欢的电台 UUID 集合
  "dislikedStationIds": {}, // 必填；当前不再推荐的电台 UUID 集合
  "tagWeights": { // 必填；用于本地排序的标签权重
    "ambient": 2, // 范围 -6..8；默认值: 0
    "jazz": -1.5 // 可为小数，不表示全局封禁
  },
  "history": { // 必填；以时间戳为键，最多 24 项，最新优先
    "2026-09-13T00:00:00.000Z": {
      "station": {
        "id": "960cf833-0601-11e8-ae97-52543be04c81", // 必填；Radio Browser stationuuid
        "name": "SomaFM Groove Salad", // 必填；电台显示名
        "streamUrl": "https://ice6.somafm.com/groovesalad-128-mp3", // 必填；搜索时的解析 URL
        "tags": {"ambient": true, "downtempo": true} // 必填；归一化小写标签集合
      },
      "listenedAt": "2026-09-13T00:00:00.000Z" // 必填；ISO 8601 时间
    }
  }
}
```

设计把口味保持为可导出的小对象，不引入账号和服务器用户表。为快速恢复历史，内嵌必要的电台快照；但每次真正开播仍通过 click counter 获取最新 URL。

## 第六章：技术架构

```text
浏览器层：React UI、HTMLAudioElement、localStorage
            |
            v
本地应用层：Express 同源 API，校验参数、缓存目录、设置描述性 User-Agent
            |
            v
外部目录层：Radio Browser 多镜像，搜索、健康过滤、click counter
            |
            v
直播内容层：浏览器直连第三方电台，本服务不转发音频
```

| 库名 | 用途 | 为何优于替代方案 | 大致包体积 |
|---|---|---|---|
| React 19 | 播放与队列状态 UI | 交互状态相关且当前团队熟悉；比手写 DOM 更易验证流程 | 未知，以实际 build gzip 为准 |
| Express 5 | 同源 API 与静态服务 | 用最小中间层设置 User-Agent 并限定外部请求 | 服务端包，未知 |
| Lucide React | 成熟的播放与反馈图标 | 避免手画不一致 SVG，支持 tree-shaking | 未知，以实际 build 为准 |
| Vite 8 | 本地开发与生产构建 | 配置少，不引入本产品不需要的 SSR 约束 | 开发依赖，不进前端运行包 |

最大架构风险是“可搜索”不等于“浏览器可播”。应对方式是优先 HTTPS、记录实播失败、保留一键换台，而不是建造通用音频代理。

可替换技术原则：推荐 React + Express；若现有项目使用 Vue/Svelte 可沿用，若部署平台已有 serverless route 可替换 Express。不可变的是：目录请求与音频流解耦、外部主机白名单、本地口味可导出、直播失败可恢复。

P0 不自定义右键菜单，避免遮蔽浏览器原生链接与图片操作。电台上下文操作全部显式存在：

```text

+-- 喜欢 / 取消喜欢
+-- 不喜欢并换台
+-- 下一家
+-- 访问电台官网
```

### 7.3 空状态

| 视图 | 用户看到什么 | CTA |
|---|---|---|
| 初次播放器 | “从全球直播里，找一个此刻” | 开始收听 |
| 队列 | “选择心情或搜索后，电台会出现” | 选择心情 |

| 最近收听 | “还没有收听记录” | 关闭侧屉后开始播放 |

### 7.4 错误状态

| 触发条件 | 用户可见的提示信息 | 恢复操作 |
|---|---|---|
| 目录镜像全部超时 | 暂时联系不上全球电台目录 | 重新寻找 |
| 查询返回空 | 没有找到合适的直播电台 | 放宽关键词 |
| click counter 失败 | 这家电台暂时无法连接 | 下一家 |
| 音频解码/流中断 | 具体电台的直播流中断了 | 换台 |
| 浏览器禁止自动播放 | 浏览器暂时阻止了播放 | 再点播放 |

### 7.5 加载状态

- 目录首次请求超过 180ms：播放键出现局部 spinner，不显示整页遮罩。
- 音频缓冲：主按钮保持尺寸，替换为 spinner；当前电台信息不清空。
- 已有队列刷新：保留原队列直至新结果成功；失败只影响候选区。

## 第九章：开发优先级

### P0 - 没有这个，产品根本无法使用。交付标准：功能可用，不需要完美。

- 心情查询、直播播放/暂停/音量/换台。
- 喜欢/不喜欢与本地标签权重。
- 目录镜像失败切换、流失败恢复、click counter。
- 桌面与移动端主流程。

### P1 - 没有这个，用户第一次体验后不会回来。交付标准：功能完整，体验有连续性。

- 联合搜索（名称/城市/国家/语言）。
- 口味解释、重置、撤销不喜欢。
- JSON 备份与恢复，会话间音量记忆。

### P2 - 有了这个，用户会把产品推荐给别人。交付标准：稳定且有辨识度。

- 本地频率摘要、地理换台文案、M3U 导出。
- 基于实播成功率的本地健康分。
- PWA 与 Media Session，前提是真实设备验证。

### P3 - 有了这个，一部分用户会付费或强烈倡导。交付标准：精致且有完整文档。

- 用户自愿的端到端加密跨设备同步。
- 可安装的心情包/编辑频道，不复制或托管音频内容。

## 第十一章：开发者交接说明

### a) 实现顺序建议

你先实现服务端的搜索与 click counter，用真实响应锁定 `Station` 字段；再实现最小播放器，因为它能最早暴露编码、CORS、混合内容和流失效问题。真播通过后再加口味排序、搜索、历史和视觉打磨。

### b) 最可能导致返工的三个决策

1. 决策：是否代理音频。安全默认：不代理，浏览器直连。改变信号：HTTPS 上线后超过 35% 已检查可用电台因混合内容失败。
2. 决策：是否上账号。安全默认：本地数据。改变信号：超过 25% 的稳定用户主动导出并请求跨端恢复。
3. 决策：心情是固定还是生成。安全默认：6 个经过验证的固定频道。改变信号：搜索输入的 60% 无法归入这 6 类。

### c) 哪里要严格，哪里可以灵活

- 第一、五、六章是约束：它们保护内容边界、数据所有权和外部请求安全。
- 第三、七、十章是约束：状态、恢复、无障碍和数字验收不可重新解释。
- 第二、四、八章是建议：你可以改善布局、文案、输出和惊喜时刻，只要不让它们遮住播放主任务。

### d) 已知的未知项

- 此处未解决：生产网络、中国大陆网络和移动 Safari 下的真实电台可播率。
- 此处未解决：稳定收听多少分钟应计入更强的正向偏好；P0 只用显式喜欢。
- 此处未解决：Radio Browser 社区运行的镜像长期 SLA；产品必须将其当作无 SLA 外部依赖。
